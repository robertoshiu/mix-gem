## Problem Statement

`/mes/analytics`（`equipment-monitor/src/app/mes/analytics/page.tsx`）目前是 6 個高密度分頁
（VPP / APC R2R / Yield Forecast / Reliability / Cross-Process Opt / Multi-Fab），每頁是
「slider + canvas 圖 + KPI 方塊」的平鋪堆疊。三個問題：

1. **不直覺**：6 個分頁平鋪，標題是縮寫（VPP、APC R2R），沒有總覽，使用者無法一眼掌握全貌，
   也不知道每個分頁在幹嘛、為什麼重要。
2. **不一致**：相較於首頁 `app/page.tsx` 已有的 cyberpunk 戰情室美學（發光 gauge、玻璃擬態卡、
   即時 tick 模擬），analytics 停在舊風格，像另一個 app。
3. **顯示 unicode 編碼（bug）**：多處標籤把符號用 `\uXXXX` escape 寫進 **JSX 文字節點** 或
   **JSX 雙引號屬性**，而 JSX 不解析 `\u`，於是畫面直接印出字面的 `λ`、`mm²`、`D₀`。

## What Makes This Cool（目標）

作品集／展示用，要讓觀眾說「哇」。觀眾**兩者都要**（半導體內行 + 一般技術面試官），
**清楚優先** → 漸進式揭露（大標題講人話、專業細節收在下一層）。

「哇」的主軸：**Hero 總覽講故事** —— 進頁先看到一個「全廠健康度」總覽，一眼掌握重點，
再往下鑽到單一製程／模組。

加碼需求（使用者明確指定）：**資料要「活」**
- 動態資料持續不斷變動，不同分類的事件都要持續發送。
- 模擬資料準備多一點，用**雜湊隨機組合**方式生成。
- 準備 **3 分鐘不重複** 的模擬資料，**每 3 分鐘循環播放**。

## Constraints

- 純前端 Next.js（client-side simulator），無真實後端資料。
- 模擬資料必須**確定性**（hash-seeded，可重現）且**不重複**（3 分鐘內），並可**無縫循環**。
- 維持既有測試（各 Tab 都有 `__tests__`）。
- 不破壞 6 個分析模組現有的計算引擎（`yield-engine` 等）——那是真正的深度，保留。

## Premises（已與使用者確認，四項全同意）

1. 沿用首頁 `app/page.tsx` 已有的 cyberpunk 戰情室設計語言，不另創一套；一致性本身帶來專業感。
2. unicode 亂碼是必修的 table stakes（半天可清），但不是這次重點；真正工作是 Hero + 活資料。
3. 重用現有 sim 基礎建設（`secs-gem-sim-engine` 的 rolling buffer / scenario cycling、
   `mulberry32` PRNG、`hashCode`、`process-store` 的 tick 模式），不從零寫資料引擎。
4. Hero 總覽是新增的頂層，不取代 6 個分頁；6 模組變成「鑽進去」的細節層。

## Approaches Considered

### Approach A:「修補對齊」最小可行版
只修 unicode + 換上首頁樣式 + 各分頁加一句人話。Effort S–M / Risk Low。
缺點：沒有 Hero 與活資料，使用者要的「哇」沒交付。Completeness 5/10。

### Approach B:「Hero 總覽 + 活資料」理想架構 ★選定
新增「全廠健康度 Hero」總覽 + 3 分鐘不重複雜湊種子模擬迴圈（多類別事件持續串流）+
6 分頁升級到首頁設計語言 + unicode 一次修乾淨。Effort L / Risk Med。Completeness 10/10。

### Approach C:「電影感劇本巡演」創意版
3 分鐘自動播放的 fab 故事，6 模組變「場景」，鏡頭自動推進。
對被動觀眾「哇」最強，但導演層較客製。Completeness 9/10（不同 kind）。
→ 已決定當作 B 的後續：B 的 Hero 預留「播放」按鈕接口，未來把 C 長上去。

## Recommended Approach（B 的實作藍圖）

### 1. 修 unicode 亂碼（table stakes，先做）

**根因**：`\uXXXX` 在 JSX 文字節點與 JSX 雙引號屬性中**不會**被解析；只有寫在 `{...}` JS 運算式
（template literal、字串字面、canvas `ctx.fillText`）裡才會。

**確切需修位置（會印出字面 escape）**：
- `YieldTab.tsx`：55（`label="D₀ avg"`）、57（`label="α cluster"`）、
  63、67、70、78（JSX 文字）
- `ApcTab.tsx`：61（`label="EWMA λ"`）、81、88（JSX 文字）
- `ReplicationTab.tsx`：47（`label="Transfer R²"`）、84、88、102（JSX 文字）
- `OptimizationTab.tsx`：75（JSX 文字 `≥`）
- `ReliabilityTab.tsx`：36（`label="AF @125°C"`）、61、70（JSX 文字）

**已正確、不要動**（在 `{}` / canvas 裡）：YieldTab 56；ApcTab 55、64；ReplicationTab 165、253；
OptimizationTab 70；ReliabilityTab 208；DopantPanel 205；ThermalBudgetPanel 83。

**修法**：把重複出現的符號抽成共用常數，用 `{}` 渲染，避免再犯：
```ts
// src/lib/analytics/symbols.ts
export const SYM = {
  lambda: 'λ', mu: 'µ', alpha: 'α', sub0: '₀', sup2: '²',
  plusminus: '±', leftright: '↔', gte: '≥', deg: '°', times: '×', dash: '—',
} as const;
```
渲染改成 `<KpiBox label={`D${SYM.sub0} avg`} />`、`Cluster {SYM.alpha}` 等。
（建議加一條 lint/test 守門：grep JSX 文字與屬性中的 `\\u`，禁止再出現。）

### 2. 活資料引擎:3 分鐘不重複、雜湊種子、可循環

新增 `src/lib/analytics/analytics-sim.ts`，建在現有 sim 基礎上：
- **時間軸**：固定 frame 步進（例如每 2s 一 tick，3 分鐘 = 90 frames），跑完回 frame 0 無縫循環。
- **確定性 + 不重複**：以 `hashCode(category + frameIndex + seed)` 餵 `mulberry32`，
  每個類別在每個 frame 取不同種子 → 序列確定、可重現、3 分鐘內不重複。
- **多類別事件持續發送**：定義事件類別池（yield excursion、APC drift、reliability alarm、
  multi-fab divergence、tool maintenance、recipe change…），每 tick 依機率從各池抽事件，
  保證各類別都持續有東西冒出來。事件進 rolling buffer（沿用 `secs-gem-sim-engine` 模式）。
- **資料池用雜湊隨機組合生成**：機台 ID、lot ID、製程步驟、數值偏移等，從基礎池以 hash 組合
  產生大量變體 → 「準備多一點」的模擬資料。
- 暴露 hook（如 `useAnalyticsSim()`）給 Hero 與各分頁訂閱當前 frame 的快照與事件流。

### 3. Hero 總覽:全廠健康度

在 `AnalyticsTabBar` 之上、`page.tsx` 裡新增 `<FabHealthHero />`：
- 頂部一行 **大標題 KPI gauge**（重用 `CyberpunkGaugeCard`）：全廠 Yield、OEE、可靠度風險、
  多廠一致性 —— 由 6 模組聚合而來，數字隨活資料持續跳動。
- **活事件流**（重用 `EventFeed` / `FacilityTab` 模式）：多類別事件持續滾入，色碼分類，
  讓畫面「動起來」。
- **製程健康度條**：8 製程的狀態一目了然，點任一個 → 切到對應分頁/模組鑽下去。
- 預留一個 **「▶ 播放劇本」** 按鈕接口（給未來的 Approach C）。
- 漸進式揭露：每個 KPI/區塊用人話一句說明（外行看懂），hover/展開才露專業細節（內行滿足）。

### 4. 6 分頁升級設計語言

各 Tab 的容器、卡片、KpiBox、按鈕換用首頁的 design tokens（玻璃擬態、accent 色、發光邊框、
圓角）；canvas 圖配色對齊首頁；每個分頁標題下加一句人話（例：「APC R2R — 跑對跑修正，
讓每片晶圓回到目標值」）。各分頁 KPI 接活資料 buffer，數字持續變動。

### 建議實作順序
1. unicode 修正 + `symbols.ts`（半天，立刻消除壞掉觀感）。
2. `analytics-sim.ts` 活資料引擎 + `useAnalyticsSim` hook（核心複雜度）。
3. `FabHealthHero` 接活資料。
4. 6 分頁樣式升級 + 接 buffer + 人話標題。
5. 測試補強（sim 確定性/不重複/循環、Hero render、unicode 守門 test）。

## Open Questions

- Hero 的聚合 KPI 要哪幾顆？（建議 Yield / OEE / Reliability Risk / Multi-Fab Consistency，待確認）
- 各分頁是否全部接活資料持續跳動，還是部分維持使用者拉 slider 的互動探索模式？（兩者可並存）
- 3 分鐘循環是否要在 UI 顯示進度（例如一條細進度條 / 「shift 03:00 loop」），讓觀眾知道在循環？

## Success Criteria

- 全頁無任何字面 `\uXXXX`／亂碼字串（含一條防回歸 test）。
- 進頁 5 秒內，外行人能講出「這頁在看整廠健不健康」。
- Hero 與分頁數字/事件在不操作時持續變動；連看 3 分鐘以上不出現明顯重複，且循環無縫。
- 視覺與首頁 `app/page.tsx` 同一條設計語言，截圖/錄影看起來像同一個高級產品。

## What I noticed about how you think

- 你選方案時不是只挑「最炫」，而是直接把實作需求講清楚：「動態資料要持續不斷變動」「3 分鐘不重複」
  「雜湊隨機組合生成」。這是已經在腦中跑過一遍實作的人才會講的細節 —— 你要的不是花俏，是「可信地活著」。
- 「清楚優先」+「兩者都要」這個取捨選得很準。很多人做作品集會往「炫到看不懂」偏；你選了
  漸進式揭露，代表你在意的是「讓人懂」這件事本身,那通常是好品味的訊號。

## Eng Review Revisions (2026-05-28)

Decisions from /plan-eng-review that revise the approach above:

- **D1 — Live-data engine: reuse, don't build new.** `dashboard-facility-engine.ts` already
  is the deterministic, hash-seeded (`hashSeed`+`mulberry32`), 180-tick=3-min, multi-category,
  rolling-buffer engine the spec describes. Extract a shared sim layer from it; do NOT build a
  new `analytics-sim` on `secs-gem-sim-engine`.
- **D2 — `AnalyticsEventFeed` is a duplicate** of `EventFeed` (decoupled, zero risk to the
  shipping facility component). Generalizing the two into one is deferred to TODOS.md.
- **D3 — Hero KPIs are single-source:** tick → existing tab engines (`yield-engine` etc.) →
  Hero aggregates. No second copy of the math.
- **D5 — Shared `KpiBox`** replaces the 6 duplicated inline copies; home tokens live there once.
- **D6 — Unicode regression guard = local ESLint rule** flagging `\u` escapes in
  JSXText/JSXAttribute (not `no-restricted-syntax` alone — needs a small local rule).
- **D7 superseded → all 6 tab charts migrate canvas → recharts** in this PR (TODO2 pulled in-scope).
- **D9 superseded → all 6 tabs go live** (tick-driven, slider as takeover) in this PR (TODO1 pulled in-scope).
- **Baked-in requirements:** single tick driver in the store (cleared on unmount, mirror
  `FacilityTab.tsx:22`); tick-driven render behind a `useClientReady()` hydration gate; bounded
  ring buffer for the event feed; granular zustand selectors + `React.memo` on KpiBox/charts.
- **Scope note:** with all-6-live + all-recharts, the 6 tab components are effectively a rewrite
  of their chart + data layers, not incremental patches. Deliberate Boil-the-Lake call for a
  portfolio piece.
- **PRNG consolidation:** one `lib/prng.ts` (`mulberry32`+`hashSeed`); migrate the three existing
  copies. CRITICAL regression: existing sim tests must pass byte-identical after the swap.

## Design Review Decisions (2026-05-28)

From /plan-design-review. Initial design completeness 4/10 → 8/10.

- **Hero visual anchor:** one large composite **Fab Health Score** (0–100, weighted from the
  4 sub-metrics) is THE anchor; the 4 gauges (Yield/OEE/Reliability/Multi-Fab) shrink to
  supporting indicators. Fixes "no single visual anchor" + the card-mosaic risk.
- **Motion + a11y (always-live page):** explicit ▶/⏸ play-pause control (defaults to playing,
  satisfies WCAG 2.2.2 for auto-updating content, doubles as screenshot pause) + respect
  `prefers-reduced-motion` (freeze to latest snapshot) + `aria-live="off"` on per-tick values
  with ONE polite region announcing only new critical events.
- **States:** skeleton-shimmer loading until first tick; sim error → last-good snapshot +
  "simulation paused" notice (never blank); cold-start gauges "—", feed "Awaiting fab events…".
- **Live-tab slider takeover:** moving a slider pauses that tab's live updates + shows
  "PAUSED — exploring" badge + "Resume live" button; Hero keeps running.
- **Loop legibility:** "SHIFT mm:ss LOOP" pill counts up + thin progress bar so viewers read
  "live loop," not "frozen."
- **Responsive:** mobile <640px → Health Score full-width top, 4 sub-gauges 2×2, process strip
  horizontal-scroll, trend + feed stack; touch targets ≥44px.
- **A11y details:** process pills are real `<button>`s, keyboard-focusable, cyan focus ring;
  plain captions use `--text2` (#94A3B8 ~7:1) and stay ≥14px.
- **Token note:** `--sf-*` already alias `--smartfactory-*` (globals.css:194+) — tokens are
  shared; the redesign aligns the glassmorphism *treatment* (blur/glow/radius/gradient), not tokens.
- **Deferred:** formalize a DESIGN.md via /design-consultation → TODOS.md.
